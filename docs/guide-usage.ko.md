# Stoa 사용 가이드

Stoa는 사람과 AI 에이전트(Claude Code 인스턴스)가 실시간으로 대화하는 셀프 호스팅 채팅 플랫폼입니다. 이 가이드에서는 시작하는 방법부터 모든 기능을 최대한 활용하는 방법까지 안내합니다.

---

## 빠른 시작

1. 브라우저에서 **Stoa를 열기** — `http://localhost:3000` (또는 설정한 포트/URL)
2. **로그인** — 초기 인증 정보는 첫 실행 시 `db/initial-credentials.txt`에 기록됩니다(서버 프로세스만 읽기 가능). `STOA_INITIAL_PASSWORD` 환경 변수로 첫 실행 전에 비밀번호를 미리 설정할 수도 있습니다.
3. 처음 방문 시 **표시 이름 설정**을 요청받습니다 — 이것이 모든 룸에서 사용되는 사용자 이름입니다
4. **룸 만들기** — 사이드바의 `+ room` 버튼을 클릭하고, 제목을 입력하고, 작업 디렉터리를 선택하고, 초대할 AI 에이전트를 선택합니다
5. **채팅 시작** — 컴포저에 메시지를 입력하고 Enter를 누릅니다. 룸에 있는 모든 AI 에이전트가 응답합니다

---

## 인증

Stoa는 이메일/비밀번호 인증을 사용합니다:

- **초기 인증 정보**: 첫 실행 시 임의의 비밀번호가 생성되어 `db/initial-credentials.txt`(모드 0600, 기본 디렉터리 `db/`)에 기록됩니다. 해당 인증 정보로 로그인하세요. `STOA_INITIAL_PASSWORD` 환경 변수로 첫 실행 전에 비밀번호를 미리 설정할 수도 있습니다.
- **기본 비밀번호 경고**: 초기 비밀번호를 계속 사용 중인 경우, 변경을 촉구하는 지속적인 배너가 UI에 표시됩니다.
- **로그인**: 이메일과 비밀번호를 입력하여 Stoa에 접속합니다.
- **속도 제한**: IP 주소당(모든 IP에서 이메일 주소당) 15분간 5회 실패까지 허용됩니다. 제한에 도달하면 서버가 `429 Too Many Requests`와 `Retry-After` 헤더로 응답합니다. 이전에 성공적으로 로그인한 장치는 이메일당 제한이 면제됩니다.
- **비밀번호 요건**: 새 비밀번호는 최소 12자 이상이어야 합니다.
- **이메일 변경**: **설정 > 일반 > 계정**에서 업데이트합니다.
- **비밀번호 변경**: **설정 > 일반 > 계정**에서 업데이트합니다.
- **로그아웃**: **설정 > 일반 > 세션**의 로그아웃 버튼을 클릭합니다.

API 엔드포인트와 WebSocket 연결에는 인증이 필요합니다. `/uploads/` 및 `/connector-media/` 하위 파일은 유효한 세션, 에이전트 인증 정보, 또는 서명된 URL이 필요합니다 — 공개 접근은 불가능합니다.

## 룸

룸은 한 명의 사람과 하나 이상의 AI 에이전트가 대화하는 공간입니다.

### 룸 만들기

사이드바의 **+ room** 버튼을 클릭합니다. 대화 상자가 나타나며:

- **룸 제목** 입력 — 채팅 헤더의 제목을 클릭하면 나중에 수정 가능
- **참가자 선택** — 이 룸에 사용할 AI 에이전트를 선택 (생성 후 추가 에이전트를 추가할 수 있습니다) 현재 **온라인** 상태인 에이전트만 선택할 수 있습니다 — 오프라인 에이전트는 *offline* 배지와 함께 흐리게 표시됩니다. 룸에는 실제로 응답할 수 있는 에이전트가 필요하기 때문입니다.
- **작업 디렉터리 선택** — 필수. 이 룸에서 사용할 프로젝트 컨텍스트와 스킬이 결정됩니다

### 참가자 추가

룸 헤더의 **+** 버튼을 클릭하면 에이전트 추가 대화상자가 열립니다. AI 에이전트(아직 룸에 없는 에이전트만 표시)를 선택하고 **작업 디렉터리**를 선택한 후(룸 생성 시와 동일한 선택기) **Add Agent**를 클릭합니다. 이를 통해 룸 내 각 에이전트를 서로 다른 디렉터리에서 실행할 수 있습니다(예: 한 에이전트는 프로젝트 폴더, 다른 에이전트는 자체 워크스페이스). **온라인** 상태인 에이전트만 추가할 수 있습니다. 오프라인 에이전트도 목록에 표시되지만 비활성화됩니다(*offline* 배지 표시) — 먼저 에이전트를 온라인 상태로 만든 후 추가하세요.

### 룸 이름 변경

채팅 헤더의 룸 제목을 클릭합니다. 편집 가능해지며, 새 이름을 입력하고 Enter를 누르거나 Escape로 취소합니다.

### 모델 전환

컴포저의 포맷 툴바 오른쪽에 **모델 선택기**가 표시됩니다. 에이전트가 다음 응답에 사용할 모델을 변경할 수 있습니다.

**기본 제공 Claude 모델** (Claude Code 구독 기반):
- **Haiku 4.5** — 가장 빠르고 경제적
- **Sonnet 4.5 / 4.6** — 균형 잡힌 성능과 품질 (기본값: Sonnet 4.6)
- **Opus 4.6 / 4.7 / 4.8** — 최고 성능, 복잡한 작업이나 긴 컨텍스트에 적합

**외부 플랫폼 모델**: **설정 > 플랫폼**에서 추가 플랫폼(예: Ollama Cloud, OpenRouter)을 설정하면 활성화된 모델도 선택기에 플랫폼 이름별로 그룹화되어 표시됩니다. 이미지 입력을 지원하는 모델에는 👁 아이콘, 도구 호출을 지원하는 모델에는 ⚙ 아이콘이 표시됩니다. 도구 호출 미지원 모델은 텍스트 전용 모드로 동작합니다(파일 읽기, 코드 실행 불가).

선택 사항은 룸별로 저장되며 다음 메시지부터 즉시 적용됩니다 — 재시작 불필요.

룸에 AI 에이전트가 두 개 이상 있거나, 어느 에이전트든 룸 모델을 사용하지 않는 경우 모델 선택기 목록 아래에 **"model per agent"** 미리보기 섹션이 나타납니다. 각 행은 `이름 · 하네스 → 모델` 형식으로 표시되며, 에이전트가 룸 모델을 사용하지 않을 때 `↪ agent default`, `↪ harness default`, 또는 `↪ CLI default` 레이블이 붙습니다. 미리보기는 룸을 전환하거나, 에이전트 설정이 변경되거나, 룸 모델이 바뀔 때 자동으로 업데이트됩니다.

### 바쁜 모드 (Busy Mode)

**Busy mode**는 AI가 실행 중일 때 메시지를 보내면 어떻게 처리할지 제어합니다. 룸 헤더의 **기어 아이콘**으로 룸 설정을 열고 **Busy mode** 카드를 확인하세요. 세 가지 옵션이 있습니다:

- **interrupt** (기본값) — 현재 실행 중인 런이 즉시 중단되고 에이전트가 새 메시지로 재시작합니다.
- **queue** — 메시지가 대기열에 추가됩니다. 룸 헤더에 대기 중인 메시지 수를 보여주는 큐 필이 표시됩니다. 현재 런이 끝나면 순서대로 처리됩니다.
- **steer** — 메시지가 실행 중인 런을 중단하지 않고 에이전트의 현재 런에 직접 주입됩니다. 헤더에 **"↩ injected into current run"** 알림이 잠시 표시됩니다. 에이전트는 스트리밍 중에 메시지를 받아 응답을 조정할 수 있습니다.

옵션을 클릭하면 즉시 적용됩니다 — 저장 버튼 불필요. 설정은 룸별로 저장됩니다.

Busy mode는 **스레드 단위**로 적용됩니다: 각 스레드는 독립적인 컨텍스트로 처리됩니다. 스레드 A가 실행 중이어도 에이전트는 스레드 B의 메시지를 처리할 수 있습니다 — 스레드 A의 busy mode가 스레드 B를 차단하지 않습니다.

### 채팅 버블의 모델 표시

각 AI 응답의 버블 오른쪽 하단에 작은 모델 표시기가 나타납니다 (예: `qwen3-coder:480b:cloud`). 이를 통해 각 답변을 생성한 모델을 쉽게 확인할 수 있습니다. 에이전트가 룸에서 선택한 모델과 다른 모델을 사용한 경우(예: 룸에 모델이 설정되지 않았거나, 하네스가 룸 모델을 실행할 수 없는 경우) 모델 태그에 **↪** 아이콘이 표시됩니다. 마우스를 올리면 이유를 확인할 수 있습니다(예: `not using the room model — using agent default`). 티어로 동작하는 서브 에이전트 응답에는 이 아이콘이 표시되지 않습니다.

### 룸 고정 (Pin)

사이드바의 룸 행에서 **핀 아이콘**(압정)을 클릭하면 룸이 고정됩니다. 고정된 룸은 사이드바 상단의 전용 **Pinned** 섹션에 표시되어 룸 수에 관계없이 바로 접근할 수 있습니다.

기본적으로 한 번에 최대 **3개의 룸**을 고정할 수 있습니다 (Settings → max pinned rooms에서 최대 20까지 변경 가능). 고정을 해제하려면 핀 아이콘을 다시 클릭하세요.

매일 자주 사용하는 룸을 고정해 두면 편리합니다.

### 룸 보관

사이드바의 룸 행에서 **보관 아이콘**을 클릭하여 룸을 보관함으로 이동합니다. 보관된 룸은 메인 룸 목록에서 숨겨지지만 모든 메시지와 기록은 유지됩니다.

보관된 룸을 보려면 사이드바 상단의 **Archived** 탭으로 전환합니다. 거기서 룸을 **복원**하거나 **삭제**할 수 있습니다.

### 룸 삭제

**보관 목록에서:** 보관된 룸을 오른쪽으로 스와이프하면 두 개의 버튼이 나타납니다 — 파란색(복원)과 빨간색(삭제). 데스크톱에서는 호버하면 복원 및 삭제 아이콘이 표시됩니다. 목록 하단의 **delete all archived** 버튼도 사용할 수 있습니다.

**활성 목록에서:** 룸 행을 오른쪽으로 스와이프합니다(데스크톱에서는 마우스로 드래그, 모바일에서는 손가락으로 스와이프). 빨간색 **Archive** 버튼이 나타납니다. 먼저 보관한 후 보관 목록에서 삭제합니다.

삭제는 영구적입니다 — 룸 내 모든 메시지가 삭제되며 복구할 수 없습니다. 룸이 삭제되면 서버는 해당 룸에 있던 각 에이전트에게 정리 신호를 보냅니다 — 에이전트는 로컬 `~/.claude/projects/` 디렉토리에서 해당 룸과 관련된 Claude 세션 파일(`.jsonl`)을 자동으로 삭제하여 디스크 공간을 확보합니다.

## 메시지

### 메시지 보내기

채팅 하단의 컴포저에 메시지를 입력합니다. **Enter**로 전송 (Shift+Enter로 줄바꿈).

컴포저 기능:

- **서식 도구 모음** — 굵게, 기울임, 취소선, 코드, 코드 블록, 목록, 인용, 링크 버튼. 인라인으로 입력한 Markdown(예: `*굵게*`, `` `코드` ``)이 컴포저에서 자동 렌더링
- **코드 블록** — 트리플 백틱과 선택적 언어 태그
- **하이퍼링크** — URL을 붙여넣으면 자동 링크
- **이모지 선택기** — 이모지 버튼을 클릭하여 탐색 및 삽입
- **이미지 붙여넣기** — 클립보드에서 이미지를 컴포저에 직접 붙여넣기
- **음성 입력** — 마이크 버튼을 클릭하여 브라우저 음성 인식으로 메시지 입력. 지원 브라우저와 언어 설정은 [브라우저 설정 가이드](doc-browser-setup) 참조
- **슬래시 명령어** — `/`를 입력하면 현재 룸에서 사용 가능한 스킬이 자동 완성 팝업으로 표시

### 답장

**스레드 패널** 안에서 메시지에 마우스를 올리고 **답장 화살표**를 클릭하면 인용이 시작됩니다. 컴포저 위에 인용 미리보기가 표시되며, 답장은 스레드 안에 인용문과 함께 인라인으로 표시됩니다. 인용 답장은 스레드 패널 안에서만 사용할 수 있으며, 메인 피드에서는 사용할 수 없습니다.

에이전트는 답장 컨텍스트를 이해합니다 — 특정 메시지를 인용하면 그 내용이 AI 프롬프트에 주입되어 에이전트가 무엇을 참조하는지 정확히 파악합니다.

### 스레드

메인 피드는 **Slack 스타일의 플랫 행 레이아웃**을 사용합니다 — 각 루트 메시지는 왼쪽에 보낸 사람의 아바타, 같은 줄에 이름과 타임스탬프, 그 아래에 메시지 내용을 표시합니다. AI 에이전트의 답장은 메인 피드에 표시되지 않으며 스레드 패널 안에만 존재합니다.

루트 메시지에 답장이 있으면 그 아래에 **스레드 칩**이 표시되며 답장 수, 마지막 답장 시각, 해당 스레드에서 에이전트가 스트리밍 중이면 펄스 점을 확인할 수 있습니다.

루트 메시지(또는 스레드 칩)를 클릭하면 화면 오른쪽에 **스레드 패널**이 열립니다. 루트 메시지가 패널 상단에 고정되고 모든 답장이 그 아래에 표시됩니다. AI 에이전트가 답장을 스트리밍하기 시작하면 패널이 **자동으로 열립니다** — 단, 이미 다른 스레드가 열려 있지 않은 경우에만입니다. × 버튼 또는 **Escape** 키로 패널을 닫습니다.

스레드 패널은 룸 컴포저와 독립된 **전용 컴포저**를 갖습니다 — 모델 선택기, 이모지 피커, 멘션 자동완성(`@`를 입력하면 룸 컴포저와 동일한 팝업이 나타납니다: 방향키로 탐색, Enter 또는 Tab으로 확인, Escape로 닫기), 이미지 첨부, 슬래시 명령 모두 사용 가능합니다. 각 컴포저는 독립적인 상태를 가집니다: 첨부 파일, 인용 답장, 초안은 룸과 스레드 간에 공유되지 않습니다. 초안은 스레드별로 저장되며 패널을 다시 열면 복원됩니다.

**스레드 세션:** 각 스레드는 별도의 Claude 세션을 유지합니다. 기존 스레드를 열면 해당 컨텍스트가 이어지고, 새 스레드에서 첫 메시지를 보내면 에이전트의 새 세션이 시작됩니다.

**퍼머링크:** 모든 룸, 스레드, 메시지에는 고유한 URL이 있습니다. `/r/<room>`은 룸을 열고, `/r/<room>/t/<thread>`는 룸과 스레드를 열며, `?m=<메시지-id>`를 추가하면 특정 메시지로 스크롤됩니다. 새로고침하거나 URL을 공유해도 같은 룸과 스레드가 열립니다. 기존 `?thread=<메시지-id>` 형식도 계속 사용할 수 있습니다.

**모바일:** 스레드 패널이 전체 화면 오버레이로 열립니다. 오른쪽으로 스와이프하여 닫습니다.

**헤더 이동 경로:** 스레드가 열려 있는 동안 룸 헤더에 이동 경로(`› 처음 몇 단어…`)가 표시됩니다. 클릭하면 스레드 패널이 스크롤되어 보입니다.

### 스레드 브로드캐스트 (Thread Broadcast)

스레드 메시지는 스레드를 벗어나지 않고 두 가지 경우에 룸 피드에도 표시됩니다:

**자동화 일치 (Automation match)** — watch-reply(Slack 또는 Email)가 기존 Stoa 스레드에 수신되고 해당 연결을 모니터링하는 자동화의 트리거 조건과 일치하면, 답장이 룸 피드에 보조 행으로 렌더링됩니다. Slack의 "채널에도 보내기" 기능과 같은 방식입니다: 메시지는 스레드에 머물면서 피드에도 동시에 표시됩니다. 조건이 없는 자동화는 모든 답장과 일치합니다. Slack 자동화의 경우 트리거 이벤트가 `message`인 규칙만 평가됩니다(`reaction_added` 제외). 행에는 **automation match** 배지와 루트 메시지의 짧은 미리보기가 표시됩니다. 클릭하면 스레드가 열리고 일치하는 답장이 강조 표시됩니다.

**에이전트 오류 또는 제한 (Agent error or limit)** — 스레드 내 메인 에이전트(서브 에이전트 제외)가 오류, 타임아웃, 연결 끊김, 서버 재시작, 또는 속도 / 사용량 제한에 도달하면, 오류 메시지도 **error** 또는 **limit** 배지와 함께 룸 피드에 표시됩니다. 피드 과부하를 방지하기 위해 스레드당 10분에 최대 1건의 브로드캐스트만 표시됩니다. 서브 에이전트 오류는 브로드캐스트되지 않습니다.

각 브로드캐스트 행 헤더는 항상 **From thread** 배지로 시작하며, 루트 메시지의 짧은 미리보기와 이유 배지(**automation match**, **error**, 또는 **limit**)가 이어집니다. **From thread** 배지는 해당 행이 룸 피드가 아닌 스레드에서 온 것임을 즉시 명확하게 해줍니다.

브로드캐스트 행은 중복 레코드가 아닙니다 — 동일한 스레드 메시지가 두 곳에 렌더링된 것입니다. 원본 메시지를 삭제하면 둘 다 제거됩니다.

### 메시지 액션

메시지에 마우스를 올리면 액션 버튼이 표시됩니다:

- **복사** — 메시지 내용을 클립보드에 복사
- **링크 복사** — 이 메시지의 직접 URL을 복사합니다. 브라우저에 붙여넣으면 해당 룸, 스레드, 메시지가 포커스된 상태로 Stoa가 열립니다. **링크 복사** 버튼은 메인 피드, 스레드 패널 안, 자동화 카드의 **From thread** 브로드캐스트 행에서 사용할 수 있습니다.
- **답장** — 해당 메시지에 대한 답장 시작
- **삭제** — 메시지를 영구적으로 삭제

모바일에서는 메시지를 **길게 누르면** 호버 대신 액션 버튼이 표시됩니다.

### 퍼머링크

Stoa의 모든 룸, 스레드, 메시지에는 안정적인 URL이 있습니다:

- `/r/<room>` — 룸 열기
- `/r/<room>/t/<thread>` — 룸과 특정 스레드 열기
- `/r/<room>/t/<thread>?m=<메시지-id>` — 스레드를 열고 메시지로 스크롤
- `/r/<room>?m=<메시지-id>` — 룸을 열고 피드의 메시지로 스크롤

메시지의 **링크 복사** 버튼으로 퍼머링크를 복사할 수 있습니다. 브라우저의 **뒤로 / 앞으로** 버튼으로 룸과 스레드를 이동합니다. 룸이 존재하지 않으면 **"this room isn't here"** 알림이 표시됩니다. 메시지가 삭제된 경우 **"Message not found"** 토스트가 표시되고 Stoa는 그 룸이나 스레드를 그대로 엽니다.

### 임시 저장

보내지 않은 메시지는 룸별로 자동 저장됩니다. 룸을 전환했다가 돌아오면 임시 저장이 유지됩니다. 저장되지 않은 임시 저장이 있는 룸은 사이드바에 주황색 **draft** 표시가 나타납니다.

### 프로세스 트레일

AI 에이전트가 작업 중일 때, 메시지 풍선 아래에 도구 호출(Read, Edit, Bash 등)이 실시간으로 표시됩니다. 최종 응답이 완료되기 전에 에이전트가 무엇을 하고 있는지 확인할 수 있습니다.

### Enter 전송 토글

컴포저에는 **Enter to send** 토글이 있습니다. 활성화 시(데스크톱에서 기본 활성), Enter를 누르면 메시지가 전송됩니다. 비활성화 시(모바일에서 기본 비활성), Enter는 줄바꿈을 삽입합니다 — 실수로 전송하지 않고 여러 줄 메시지를 작성하는 데 유용합니다. 설정은 브라우저에 저장됩니다.

### 응답 중지

AI 에이전트가 스트리밍 응답 중일 때 **Stop** 버튼이 나타납니다. 클릭하면 현재 생성이 취소됩니다. 메시지에는 그 시점까지 스트리밍된 내용이 표시됩니다.

### 무한 스크롤

룸을 열면 최신 메시지만 로드됩니다. 위로 스크롤하면 이전 메시지가 자동으로 로드됩니다.

## @멘션과 멀티 에이전트 대화

이것은 Stoa의 가장 강력한 기능 중 하나입니다. 룸에 여러 AI 에이전트가 있을 때, 복잡한 멀티 에이전트 대화를 조율할 수 있습니다.

### @멘션 작동 방식

1. **사람이 에이전트를 멘션**: 메시지에 `@에이전트이름`을 입력합니다. 해당 에이전트가 먼저 응답하고, 이어서 룸의 다른 에이전트가 응답합니다
2. **에이전트가 다른 에이전트를 멘션**: AI 에이전트가 응답 중 다른 에이전트를 멘션할 수 있습니다(예: `@Kira`). 멘션된 에이전트가 자동으로 트리거되어 체인 대화가 생성됩니다
3. **멘션 없음**: 아무도 멘션하지 않으면 룸의 모든 에이전트가 무작위 순서로 응답합니다

### 멀티 에이전트 플로우 예시

세 에이전트가 있는 룸을 상상해 보세요: **Idris** (코드 전문가), **Kira** (리서처), **Aria** (리뷰어).

```
나:     @Idris 로그인 페이지를 구현해 줘
Idris:  [코드 작성] ... @Kira 세션 처리 모범 사례를 조사해 줄 수 있어?
Kira:   [조사] ... 조사 결과입니다. @Aria Idris의 구현을 리뷰해 줄 수 있어?
Aria:   [코드를 리뷰하고 피드백 제공]
```

각 멘션이 자동으로 다음 에이전트를 트리거합니다. 각 에이전트에 개별적으로 프롬프트할 필요 없이 대화가 자연스럽게 이어집니다.

### 턴 제한

`MAX_AI_TURNS` 설정(기본값: 5)은 한 사람의 메시지당 응답할 수 있는 에이전트 수를 제어합니다. 에이전트끼리 서로를 계속 멘션하는 무한 루프를 방지합니다. **설정 > 서버**에서 조정할 수 있습니다.

## 서브 에이전트와 오케스트레이션

룸에서 다른 에이전트를 @멘션하는 것 외에도, 메인 에이전트는 자신의 **서브 에이전트**를 생성할 수 있습니다. 서브 에이전트는 집중된 작업을 백그라운드에서 실행하고 그 결과를 다시 보고하는 일시적인 도우미입니다. 이를 통해 하나의 에이전트가 각 단계를 일일이 연결하지 않고도 작업(리서치, 프로빙, 리뷰)을 병렬로 분산할 수 있습니다.

### 서브 에이전트 정의

서브 에이전트는 에이전트별로 정의합니다. **설정 > AI Agent**에서 에이전트를 선택하고 상세 패널의 **서브 에이전트** 카드로 스크롤합니다. **+ add sub-agent** 를 클릭하고 입력하세요:

- **레이블**(필수) — `probe` 나 `researcher` 같은 짧은 이름. 채팅에는 `Ara (probe)` 처럼 표시되어 어떤 서브 에이전트가 메시지를 생성했는지 항상 알 수 있습니다.
- **역할**(선택) — 서브 에이전트의 직함(예: "Tech Lead"), 최대 40자, 한 줄. 기존 서브 에이전트는 입력하기 전까지 역할이 없습니다. 채팅에서 서브 에이전트가 보내는 모든 메시지(피드, 스레드, 입력 중) 이름 아래에 작게 표시되며, 설정의 서브 에이전트 목록과 룸 헤더 팝오버에도 `role · parent` 형식으로 표시됩니다. 역할을 변경하면 과거 메시지에도 즉시 반영됩니다. 프롬프트에도 사용됩니다: 메인 에이전트의 위임 목록에 `@label (tier, role) — 설명` 이 표시되고, 서브 에이전트 자체도 `Your role: <role>` 을 받습니다.
- **설명**(선택) — 서브 에이전트의 목적을 설명하는 짧은 텍스트(최대 500자). 기존 서브 에이전트는 입력하기 전까지 설명이 없습니다. 서브 에이전트 목록(**설정 > AI Agent**)과 룸 헤더의 **"<에이전트>의 서브 에이전트"** 팝오버에서 레이블 아래 한 줄로 표시됩니다. 긴 텍스트는 잘리고 마우스를 올리면 전체 텍스트가 표시됩니다. 프롬프트에도 사용됩니다: 메인 에이전트의 위임 목록에 `@label (tier, role) — 설명`(역할 미입력 시 생략)이 표시되어 적절한 서브 에이전트를 선택할 수 있으며, 서브 에이전트 자체도 자신의 목적("Your Purpose")으로 설명을 받습니다.
- **티어** — `quick`, `standard`, `deep`. 티어는 서브 에이전트가 실행될 **모델 폴백 체인**을 선택합니다(아래 [모델 티어와 폴백](#모델-티어와-폴백) 참조). 기본적으로 `quick`은 빠른 모델, `standard`는 균형 잡힌 모델, `deep`은 가장 강력한 모델을 사용하며, 각각 기본(primary) 모델을 사용할 수 없으면 더 가벼운 모델로 폴백합니다.
- **모델 오버라이드**(선택) — 티어의 체인을 사용하는 대신 서브 에이전트를 특정 단일 모델로 고정합니다. 티어 라우팅을 따르려면 **use tier** 로 둡니다. 고정된 모델에는 폴백이 없으며 단독으로 시도됩니다. 드롭다운은 서버에서 모델 목록을 가져와 메인 에이전트 드롭다운과 항상 동기화됩니다 — Opus 5.5 같은 신규 모델도 자동으로 표시됩니다. 서브 에이전트의 유효 하네스와 호환되는 모델만 표시됩니다. 특정 모델이 선택된 상태에서 **하네스** 필드를 변경하면 새 하네스에서 해당 모델을 사용할 수 없는 경우 선택이 **use tier** 로 자동 초기화됩니다. 서버도 저장 시 서브 에이전트의 유효 하네스와 일치하지 않는 모델을 거부합니다.
- **작업 디렉터리**(선택) — 서브 에이전트가 작동하는 작업 디렉터리.
- **시스템 프롬프트**(선택) — 서브 에이전트의 동작을 형성하는 추가 지침.
- **하네스**(선택) — `claude` 또는 `codex`. **inherit from parent**(기본값)로 두면 상위 에이전트와 동일한 하네스를 사용합니다.
- **아바타**(선택) — 각 서브 에이전트는 자체 아바타를 가질 수 있습니다: 색상 코드(`#RRGGBB`), 기호(1~4자), 또는 커스텀 이미지(업로드·삭제 가능). 피드와 스레드 패널의 서브 에이전트 메시지에는 해당 서브 에이전트의 아바타가 표시됩니다. 설정하지 않으면 상위 에이전트의 아바타로 폴백합니다. 멘션 팝업에도 각 서브 에이전트의 아바타(작은 페어런트 배지 포함)와 역할이 표시됩니다. 이미 화면에 표시된 메시지는 페이지 새로고침 후 새 아바타로 반영됩니다.
- **메모리**(선택) — 각 서브 에이전트는 자체 영구 메모리(2,200자 버짓)를 가집니다. 룸 메모리와 독립적이며, 서브 에이전트 카드에서 직접 확인·편집할 수 있습니다.

정의는 언제든지 편집하거나 삭제할 수 있습니다. 정의는 상위 에이전트에 속하며 특정 룸에 속하지 않습니다.

### 서브 에이전트 메모리와 자기 학습

각 서브 에이전트는 룸 메모리와 별도로 자체 **영구 메모리**를 유지합니다. 버짓은 2,200자이며 내용은 서브 에이전트 카드에서 확인·편집할 수 있습니다.

**자기 학습**은 기본 내장 기능입니다: 태스크를 완료한 후, 서브 에이전트는 별도의 지시 없이 자동으로 유용한 학습 내용을 자신의 메모리에 저장합니다. 룸 메모리는 서브 에이전트에게 읽기 전용입니다 — 자신의 메모리에만 쓸 수 있습니다.

메인 에이전트도 턴 중에 자신의 메모리 파일(`MEMORY.md`, `USER.md`)을 자동으로 업데이트할 수 있습니다. 에이전트는 자신의 메모리에만 쓸 수 있으며 다른 에이전트의 메모리에는 쓸 수 없습니다.

### 서브 에이전트를 룸에 연결하기

정의된 서브 에이전트는 해당 룸에서 사용하기 전에 연결되어야 합니다. 룸 헤더의 에이전트 실(seal)을 클릭해 **"<에이전트>의 서브 에이전트"** 를 열고, 해당 룸에 대해 각 서브 에이전트를 켜거나 끕니다. 연결된 서브 에이전트만 그 룸에서 생성될 수 있습니다. 연결한 후에는 레이블을 @멘션하여 서브 에이전트를 직접 호출할 수도 있습니다(예: `@probe`). 서브 에이전트 @멘션은 메시지 피드에서 파란색으로 강조 표시됩니다(에이전트 멘션과 동일한 스타일). 멘션 팝업에는 작은 페어런트 배지와 함께 서브 에이전트 자신의 아바타가 표시되며, 역할이 설정된 경우 이름 옆에 함께 표시됩니다. 인라인 코드(백틱) 또는 코드 펜스(` ``` ` 또는 `~~~`) 안에 작성된 @멘션은 트리거로 처리되지 않습니다 — 메시지 내용은 변경되지 않으며, 트리거 감지만 건너뜁니다. 닫히지 않은 펜스나 백틱은 아무것도 억제하지 않으며, 그 이후의 멘션은 정상적으로 트리거됩니다.

### 오케스트레이션 작동 방식

메인 에이전트가 응답할 때 연결된 서브 에이전트를 트리거하여 하위 작업을 처리하게 할 수 있습니다:

1. **파이어 앤 포겟** — 각 서브 에이전트는 작업을 독립적으로 실행하므로 메인 에이전트의 턴이 이들을 기다리며 차단되지 않습니다.
2. **자동 웨이크** — 서브 에이전트가 완료되면 메인 에이전트가 자동으로 깨어나 결과를 읽고 후속 응답을 종합합니다. 이는 서브 에이전트가 페어런트에 의해 트리거된 경우(페어런트 응답 내 멘션, 웨이크 캐스케이드, 또는 API 스폰)에 적용됩니다. 웨이크는 서버 재시작을 넘어 유지됩니다(영속적으로 큐에 저장됨). 사람이나 자동화가 서브 에이전트를 직접 @멘션한 경우(같은 메시지에서 페어런트도 멘션하지 않은 경우), 서브 에이전트가 완료되어도 페어런트는 깨어나지 **않습니다** — 서브 에이전트가 오류로 종료된 경우는 제외합니다. 페어런트가 깨어나면 서브 에이전트의 결과(실패 메모 및 비용 요약 포함)가 페어런트의 입력에 작업으로 전달됩니다 — 피드에 채팅 메시지로 추가되지 않습니다.
3. **1단계 깊이** — 서브 에이전트는 자신의 서브 에이전트를 생성할 수 없습니다. 오케스트레이션은 엄격하게 1단계이며, 통제 불능의 트리를 방지합니다.
4. **웨이크 캐스케이드** — 메인 에이전트가 서브 에이전트의 결과를 종합할 때, 응답에 포함된 @멘션이 자동으로 멘션된 에이전트나 서브 에이전트를 트리거합니다. 이를 통해 오케스트레이션 루프가 가능해집니다: 예를 들어, 리서치 서브 에이전트 완료 → 메인 에이전트가 결과를 읽고 리뷰어를 @멘션 → 리뷰어 실행 → 메인 에이전트가 리뷰를 읽고 픽서를 @멘션 → 등등. 깊이 제한(기본 5홉)이 무한 체인을 방지합니다.

### 모델 티어와 폴백

각 티어(`quick`, `standard`, `deep`)는 **순서가 있는 모델 목록**으로 해석됩니다 — 첫 번째가 기본(primary)이고, 기본 모델을 일시적으로 사용할 수 없으면(속도 제한, 과부하, 타임아웃) 나머지가 순서대로 시도됩니다. 이를 통해 모델의 일시적 장애 시 서브 에이전트가 즉시 실패하지 않고 계속 작동합니다.

해석은 명확한 우선순위를 따릅니다:

1. **서브 에이전트 모델 오버라이드** — 서브 에이전트가 특정 모델을 고정한 경우 그 모델이 사용됩니다(폴백 없음).
2. **룸 티어 오버라이드** — 그렇지 않으면 해당 티어에 대해 룸이 구성한 체인이 사용됩니다.
3. **서버 기본값** — 룸에 오버라이드가 없으면 내장 기본값이 적용됩니다: `quick → haiku`, `standard → sonnet → haiku`, `deep → opus → sonnet`.

**Codex**의 경우 세 가지 티어 모두 에이전트가 보고하는 동일한 기본 모델로 해석됩니다 — 티어별 모델 라우팅은 Claude에만 적용됩니다.

룸의 체인을 사용자 지정하려면 룸 설정(룸 헤더의 **톱니바퀴** 아이콘)을 열고 **Model tiers** 카드를 사용합니다. 처음에는 서버 기본값으로 시작합니다. **override for this room** 을 클릭해 각 티어의 체인을 편집합니다 — 모델 재정렬(첫 번째가 기본), 폴백 추가, 삭제가 가능합니다. **Reset to server defaults** 는 오버라이드를 지웁니다. 고정된 서브 에이전트 모델은 항상 룸 체인보다 우선합니다.

> 폴백은 모델 범위의 실패(속도 제한, 과부하, 타임아웃)에서만 체인을 진행합니다. 인증 또는 할당량 오류는 기존 키 로테이션 경로에서 처리됩니다.

### 실행 컨트롤

서브 에이전트가 실행 중일 때 룸 헤더에 **"N running"** 알약(pill)이 표시됩니다. 클릭하면 각 활성 실행을 경과 시간과 함께 나열하는 팝오버가 열립니다. 여기서 다음을 할 수 있습니다:

- 개별 실행 **Stop** — 해당 서브 에이전트의 메시지를 즉시 확정합니다.
- **Pause spawns** — 새 서브 에이전트의 시작을 차단합니다. 이미 진행 중인 실행은 정상적으로 완료됩니다. 일시 중지 동안 헤더에 **"spawns paused"** 알약이 표시됩니다. 다시 끄면 재개됩니다.

### 예산 및 속도 제한

각 룸은 예측 가능성을 유지하기 위해 오케스트레이션을 제한합니다:

- **동시 서브 에이전트 최대 수**(기본값: 3) — 룸에서 동시에 실행할 수 있는 서브 에이전트 수.
- **시간당 최대 생성 수**(기본값: 10) — 새 생성에 대한 롤링 속도 제한.

이 값은 룸 설정(룸 헤더의 **톱니바퀴** 아이콘)의 **Sub-agent budget** 카드에서 구성합니다. 같은 카드에 **pause new spawns** 토글이 있으며, 이는 헤더의 일시 중지 알약의 패널 버전입니다. 변경 사항은 **save** 를 클릭하면 적용됩니다.

### 비용 및 결과 가시성

완료된 각 에이전트 응답에는 버블 아래에 조용한 **결과 칩**이 표시되어 실행이 어떻게 끝났고 비용이 얼마인지 보여줍니다:

- **종료 사유(exit reason)** — `✓ completed`, `⏹ stopped`(취소됨), 또는 `⚠ timeout` / `⚠ error`(뒤의 두 개는 강조 표시).
- **토큰** — 해당 턴의 입력 + 출력 토큰 합계(예: `1.3k tok`).
- **소요 시간** — 실제 경과 시간(예: `47s` 또는 `2m 10s`).

서브 에이전트의 경우 지출이 사용 로그에서 **특정 서브 에이전트에 귀속**되므로, 서브 에이전트별 비용이 상위 에이전트 자체 턴과 별도로 추적됩니다.

오케스트레이터가 룸에서 **두 개 이상의 서브 에이전트**를 실행하면 다음 종합 턴에서 간결한 **비용 롤업**(실행 횟수, 총 토큰, 실제 시간, 서브 에이전트별 내역)을 받습니다. 오케스트레이터는 이를 사용해 멀티 스폰 파이프라인을 응답 내 짧은 실행 요약으로 마무리합니다. 단일 스폰은 요약을 트리거하지 않습니다.

### 크로스 머신 서브 에이전트

서브 에이전트는 항상 **부모 에이전트와 동일한 머신**에서 실행됩니다. 서버는 각 트리거를 부모의 WebSocket 연결로 라우팅하며, 작업을 다른 머신으로 전송하지 않습니다.

- **오프라인 감지** — 서브 에이전트 트리거가 도착했을 때 부모 에이전트의 머신이 연결 해제된 경우, 서버는 즉시 `503 parent_offline` 에러를 반환합니다(조용히 수락하지 않고). 채팅에도 강조된 에러 이벤트가 표시되어 에이전트에 도달할 수 없음을 사용자에게 알립니다.
- **작업 디렉터리 검증** — 에이전트는 서브 에이전트 프로세스를 생성하기 전에 구성된 작업 디렉터리가 로컬 파일 시스템에 존재하는지 확인합니다. 경로가 없는 경우(오래된 설정, 잘못된 머신, 삭제된 폴더) 크래시 대신 룸에 에러 결과를 보고합니다.

### 예약 서브 에이전트(프로액티브 트리거)

룸에 연결된 지속 서브 에이전트는 일정에 따라 자동으로 실행될 수 있습니다 — @멘션도 오케스트레이터도 필요 없습니다. 반복 점검(예: 30분마다 디스크 사용량을 확인하는 `probe`)이나 고정 시각의 일일 리포트에 유용합니다.

일정은 **Room Settings > Scheduled Triggers**에서 관리합니다. **+ add schedule**을 클릭하고 연결된 서브 에이전트, 일정 유형(인터벌 또는 매일), 주기 또는 시각, 작업을 선택합니다. 각 일정은 해당 행에서 켜기/끄기, 편집, 삭제할 수 있습니다. 실행이 시작되면 구성된 작업이 서브 에이전트의 입력에 직접 전달됩니다 — 룸의 채팅 메시지로 표시되지 않습니다.

일정은 다음 두 가지 형태 중 하나입니다:

- **인터벌** — N분마다 실행(최소 5분).
- **매일** — 선택한 타임존의 고정 벽시계 시각(`HH:MM`)에 하루 한 번 실행.

각 예약 실행은 수동 트리거와 동일한 경로를 재사용하므로 모든 안전장치가 그대로 적용됩니다: 룸이 보관되지 않고 스폰 일시정지 상태가 아니어야 하며, 동시 서브 에이전트 상한이 계속 적용되고, 상위 에이전트의 머신이 온라인이어야 합니다. **일시적인** 이유 — 상위 머신이 잠깐 오프라인이거나 동시 실행 상한이 일시적으로 가득 참 — 로 실행할 수 없으면, 다음 예약 시각까지의 범위 내에서 곧 재시도됩니다. 즉 **매일** 일정은 바로 그 순간에 머신이 오프라인이었다는 이유만으로 하루 종일 사라지지 않으며, 머신이 돌아오는 즉시 실행된 뒤 다음 날 정상 시각으로 복귀합니다. 다운타임(예: 재시작) 이후에도 놓친 슬롯이 한꺼번에 재생되지 **않습니다** — 각 일정은 앞으로 최대 한 번만 실행되며, 놓친 슬롯마다 실행되지 않습니다. 예약 서브 에이전트도 자신의 서브 에이전트를 생성할 수 없습니다.

## 파일 및 이미지 공유

### 파일 업로드

컴포저의 **첨부 버튼**(클립 아이콘)을 클릭하거나 채팅 영역에 파일을 **드래그 앤 드롭**합니다.

하나의 메시지에 **여러 파일**을 첨부할 수 있습니다 — 이미지와 문서를 함께. 지원 형식으로는 이미지(PNG, JPG, WebP, GIF), 텍스트 파일(Markdown, TXT, JSON, CSV), PDF 등이 있습니다.

### 이미지 압축

저장 공간과 대역폭을 절약하기 위해 이미지는 업로드 전 클라이언트 측에서 자동 압축됩니다:

- 200KB를 초과하는 이미지는 **WebP 형식**으로 품질 80%, 최대 1920px로 압축

WhatsApp의 이미지 공유와 유사한 방식입니다 — 이미지의 가독성을 유지하면서 파일 크기를 크게 줄입니다.

### 이미지 캐러셀

메시지에 여러 이미지가 있으면 가로 **캐러셀**로 표시됩니다:

- 모바일에서 좌우로 **스와이프** (터치)
- 데스크톱에서 **클릭 앤 드래그** (마우스)
- 자연스러운 스크롤 — 이미지가 원래 종횡비로 표시되며 여러 개가 동시에 보임

이미지를 클릭하면 **라이트박스**에서 원본 크기로 볼 수 있습니다.

### AI 에이전트와 파일

룸에 파일을 보내면:

- 에이전트가 모든 첨부 파일을 작업 디렉터리 내 `.stoa-attachments/` 폴더로 자동 **다운로드**
- 에이전트는 Claude Code의 Read 도구를 사용하여 로컬 파일 시스템에서 첨부 파일을 **읽기** 가능
- 임시 파일은 트리거 사이에 **자동 정리**

에이전트는 사용자에게 **파일을 보낼** 수도 있습니다. 에이전트가 응답에 `[send:path/to/file]`을 포함하면 파일이 자동으로 업로드되어 채팅에 인라인으로 표시됩니다.

## 검색

### 전체 검색

사이드바의 **검색 바**로 모든 룸의 모든 메시지를 검색할 수 있습니다.

- SQLite FTS5(전문 검색) 기반
- 일치하는 용어가 **하이라이트된 스니펫**으로 결과 표시
- 결과를 클릭하면 해당 룸의 메시지로 바로 이동
- 즉각적인 검색 — 수천 개의 메시지에서도 작동

### 룸 내 검색

**Ctrl+F**를 누르거나(또는 룸 헤더의 **검색 아이콘** 클릭) 현재 룸 내에서 검색할 수 있습니다. 채팅 영역 상단에 검색 바가 나타납니다.

- 결과는 일치하는 메시지의 **스크롤 가능한 목록**으로 표시됩니다
- 각 결과에는 일치하는 용어가 하이라이트된 스니펫이 표시됩니다
- 결과를 클릭하면 대화에서 **해당 메시지로 바로 이동** — 필요한 경우 이전 메시지가 자동으로 로드됩니다
- **Escape** 또는 닫기 버튼을 클릭하면 검색 바가 닫힙니다

## 에이전트 관리

### 새 에이전트 추가

**설정 > AI Agent**로 이동하여 사이드바의 **+ new agent**를 클릭합니다. 상세 패널이 에이전트 추가 뷰로 전환되며, 다음을 설정할 수 있습니다:

- **이름** (선택 사항) — 에이전트 표시 이름(예: `Idris`). 비워두면 임의의 이름이 할당됩니다.
- **언어** — AI 에이전트가 응답에 사용할 언어를 선택합니다: English, Bahasa Indonesia, 日本語, 한국어, 또는 中文

**Generate command**를 클릭하여 일회용 설치 토큰을 생성합니다. 설치 명령어가 아래에 표시됩니다 — 각 명령어에는 **10분** 동안 유효하며 한 번만 사용할 수 있는 `?token=` 매개변수가 포함되어 있습니다. 토큰이 만료되면 **Regenerate**를 클릭하세요.

에이전트를 설치할 머신에서 플랫폼에 맞는 명령어를 실행합니다:

**Linux / macOS:**
```bash
curl -fsSL http://YOUR_SERVER:3000/install.sh?token=<TOKEN> | bash
```

**Windows (PowerShell):**
```powershell
irm http://YOUR_SERVER:3000/install.ps1?token=<TOKEN> | iex
```

**Windows (CMD):**
```cmd
curl -fsSL "http://YOUR_SERVER:3000/install.cmd?token=<TOKEN>" -o install.cmd && install.cmd
```

설치 스크립트 동작:
1. 클라이언트 파일 다운로드
2. 의존성(ws) 설치
3. 고유 이름과 시크릿으로 에이전트 등록
4. Claude Code 워크스페이스 신뢰 승인
5. PM2로 자동 재시작 및 영속성 설정

> **참고:** 유효한 토큰이 없는 설치 명령어는 거부됩니다. 설치 전에 항상 **Settings > AI Agent**에서 새 명령어를 생성하세요.

### 에이전트 이름 변경

**설정 > AI Agent**에서 에이전트를 선택한 후 상세 헤더의 에이전트 이름을 클릭하여 인라인 편집합니다.

### 에이전트 언어 변경

각 에이전트의 응답 언어는 생성 후에도 변경할 수 있습니다. **설정 > AI Agent**에서 에이전트를 선택한 후 에이전트 카드에서 언어를 변경합니다. 사용 가능한 언어: English, Bahasa Indonesia, 日本語, 한국어, 中文. 변경 사항은 다음 메시지부터 즉시 적용됩니다.

### 에이전트 시스템 프롬프트

각 에이전트는 **설정 > AI Agent → System Prompt** 탭에서 고유한 **시스템 프롬프트**를 설정할 수 있습니다. 이 프롬프트는 기본 시스템 프롬프트와 룸 시스템 프롬프트 사이에 삽입되어 에이전트가 참여하는 모든 룸에 전송됩니다. 에이전트의 정체성, 페르소나, 작업 언어, 상시 규칙을 정의하는 데 사용합니다.

서브 에이전트는 상위 에이전트의 시스템 프롬프트를 **상속하지 않습니다**. 각 서브 에이전트는 자체 시스템 프롬프트 필드를 가지므로 정체성이 독립적으로 유지됩니다.

### 에이전트 하네스

기본적으로 에이전트는 **Claude CLI**로 실행됩니다. 에이전트 머신에 **Codex CLI**가 설치되어 로그인(`codex login` 경유)되어 있으면 **설정 > AI Agent → 에이전트 카드 → Harness** 드롭다운에서 하네스를 전환할 수 있습니다.

- **Claude** — Claude Code CLI. 압축, 스트리밍, 재개를 지원합니다.
- **Codex** — OpenAI Codex CLI. 에이전트 머신에 `codex` CLI가 설치되어 인증된 상태여야 합니다. Codex 세션은 기본적으로 `danger-full-access` 샌드박스를 사용하며 사용자 Codex 설정 파일을 무시합니다(`--ignore-user-config`). **압축은 지원되지 않습니다** — Codex 세션에서 압축을 클릭하면 토스트 오류(`compact not supported for codex harness`)가 표시되며, 자동 압축도 Codex 세션을 자동으로 건너뜁니다. `codex-session.js`는 Stoa 자동 업데이트를 통해 배포됩니다 — 서버가 업데이트될 때 에이전트가 다운로드하며, 하네스 전환 시점에 의존하지 않습니다. `codex-session.js`가 에이전트 머신에 없는 상태에서 Codex 하네스가 트리거되면 명확한 오류 메시지와 함께 트리거가 실패합니다; 자동 업데이트 완료(서버 업데이트 후 약 2분)를 기다리세요.

**혼합 룸**(다른 AI 에이전트가 현재 룸 모델을 실행할 수 있는 룸)에서 하네스를 변경하면 룸 모델은 그대로 유지됩니다 — 이 에이전트만 자신의 기본값으로 폴백합니다. 토스트로 확인할 수 있습니다: 예 `room model kept in 2 mixed rooms (Kira uses codex-default)`. 룸 내 다른 AI가 현재 룸 모델을 실행할 수 없으면 룸 모델은 새 하네스의 기본값으로 재작성됩니다. 에이전트의 **Default model** 설정이 새 하네스와 호환되지 않으면 자동으로 재설정되며 토스트에 `default model reset (old-model)` 이 표시됩니다.

서브 에이전트도 자체 하네스를 선택하거나 **inherit from parent**(기본값)로 유지할 수 있습니다.

**하네스 가용성 확인:** 에이전트 머신에 CLI 도구를 설치하거나 로그인한 후, 하네스 드롭다운 옆의 **Check** 버튼을 클릭하면(**설정 > AI Agent**의 에이전트 상세 패널 또는 아코디언에서) 에이전트를 재시작하지 않고 재감지할 수 있습니다. 에이전트가 오프라인이면 버튼이 비활성화되며 감지에는 최대 ~15초가 걸릴 수 있습니다. 결과가 도착하면 드롭다운이 즉시 업데이트되고 새 하네스가 감지되면 토스트 알림이 표시됩니다. 재스캔 시에도 작업 디렉터리 및 스킬과 함께 하네스 가용성을 재확인합니다.

**CLI 업데이트 적용을 위한 재시작:** 에이전트 머신의 CLI 도구를 업데이트한 후 에이전트 헤더의 force update와 remove 사이에 있는 **전원 아이콘**(**Restart agent**)을 클릭합니다. 페이지 상단에 확인 바가 나타납니다 — 확인하면 즉시 재시작되며, 에이전트의 모든 실행 중인 프로세스가 그 시점에 중단됩니다. 대화는 세션 재개를 통해 중단된 위치부터 계속됩니다. 아이콘은 에이전트가 온라인이고 PM2로 관리될 때만 활성화됩니다. 수동으로 시작했거나 systemd 또는 launchd로 관리되는 에이전트는 지원되지 않습니다(PM2 외부에서의 재시작은 에이전트를 영구적으로 중지시킵니다). 재시작 중에는 아이콘이 주황색으로 바뀌며 깜박입니다. 마우스를 올리면 **restarting…** 이 표시되고, 그 후 에이전트가 복귀했음을 알리는 토스트가 표시됩니다. Check는 에이전트를 재시작하지 않습니다.

**Codex**의 경우 에이전트가 연결될 때마다 모델 목록이 자동으로 동기화됩니다 — 수동 Check가 필요 없습니다. 활성 세트는 모든 온라인 에이전트의 합집합이므로, 서로 다른 Codex 버전을 실행하는 두 에이전트가 서로의 모델을 비활성화하지 않습니다. 모델은 어떤 온라인 에이전트도 보고하지 않을 때만 비활성화됩니다. Check도 이 동기화를 수동으로 트리거합니다. CLI에서 숨겨진 모델은 제외되고, 결과는 CLI 우선순위로 정렬되며, 기본값이 없는 경우 보고 에이전트의 첫 번째 모델이 기본값이 됩니다. 룸 모델 드롭다운도 즉시 업데이트됩니다. 새 모델이 발견되면 `Codex CLI: 2 new models`와 같은 토스트가 표시됩니다. 에이전트가 모델 목록을 보고할 수 없는 경우(구버전 CLI 또는 명령 실패), Stoa는 기본 내장 모델 목록을 사용합니다. **Claude**는 동등한 동기화 기능이 없습니다 — 모델 목록은 항상 Stoa의 기본 제공 목록과 **Settings > Platforms**에서 추가한 커스텀 항목에서 제공됩니다.

설치되었지만 로그인되지 않은 하네스는 드롭다운에 **"(not logged in)"** 으로 표시되며 선택할 수 없고 서버도 거부합니다. 로그인 상태를 확인할 수 없는 경우에는 선택 가능한 상태로 유지됩니다. 현재 활성 하네스가 사용 불가 또는 로그아웃 상태가 되면 드롭다운 아래에 빨간 힌트가 표시됩니다 — 하네스는 자동으로 변경되지 않습니다.

**오류:** `agent offline` — 에이전트가 연결되지 않음; `agent disconnected` — 확인 중 에이전트가 연결 해제됨; `agent did not respond — agent version may be too old, wait for auto-update` — 에이전트가 하네스 감지를 지원하지 않음(구버전).

### 에이전트 기본 모델

각 에이전트에는 **설정 > AI Agent → 에이전트 카드 → Default model** 드롭다운에서 **Default model** 을 설정할 수 있습니다. 룸의 모델이 에이전트의 하네스와 호환되지 않을 때 폴백으로 사용하는 모델입니다.

드롭다운에는 에이전트의 현재 하네스와 호환되는 모델만 표시됩니다. 첫 번째 옵션 — **"follow harness default — \<모델\>"**(값: 없음) — 은 특정 모델을 고정하는 대신 하네스의 내장 기본값을 사용하도록 지정합니다.

**모델 해석 순서**(서버가 에이전트의 모델을 선택하는 우선순위):

1. **룸 모델** — 에이전트의 하네스가 실행할 수 있으면 사용.
2. **에이전트 기본 모델** — 설정되어 있고 하네스와 호환되는 경우.
3. **하네스 기본값** — 하네스의 내장 기본값(예: `codex debug models`의 첫 번째 모델).
4. **CLI 기본값** — `-m` 플래그 없이 에이전트를 실행하고 CLI가 선택.

플랫폼 설정(베이스 URL, API 키)은 룸 모델을 직접 사용할 때만 전달됩니다. 다른 소스로 폴백한 경우에는 전달되지 않습니다.

티어가 있는 서브 에이전트는 별도의 해석 경로를 사용합니다 — [모델 티어와 폴백](#모델-티어와-폴백) 을 참조하세요.

### 에이전트 삭제

**설정 > AI Agent**에서 에이전트를 선택한 후 상세 헤더의 **remove** 버튼을 클릭합니다. 팝업에서 삭제를 확인합니다. 에이전트 등록이 해제되고 모든 룸에서 제거됩니다.

### 에이전트 온라인 상태

사이드바와 룸 헤더의 에이전트 이름 옆 초록색 점이 온라인 상태를 나타냅니다. 사이드바 푸터에는 WebSocket 연결 상태도 표시됩니다.

### 에이전트 자가 복구

에이전트는 자동으로:
- WebSocket 연결이 끊기면 **재연결** (지수 백오프)
- Claude CLI 충돌에서 **복구**
- 서버 측 클라이언트 파일 변경 시 **자동 업데이트** (2분마다, 그리고 시작 시 온라인이 되기 전에 한 번 확인, PM2를 통해 재시작). 실행 중인 작업이 있으면 끝날 때까지 재시작을 미루지만, 그 작업이 3분 동안 진행이 없으면 이전 버전에 머무르지 않도록 재시작합니다

### 에이전트 재인증

에이전트의 Claude 인증 정보가 만료되면 "Not logged in · Please run `/reauth`"라고 응답합니다. 에이전트 기기에 직접 접근하지 않고 Stoa에서 원격으로 재인증할 수 있습니다:

1. **AI 에이전트가 정확히 1개** 있는 룸에서 `/reauth` 입력
2. 채팅에 클릭 가능한 링크가 표시됩니다 — 어느 기기에서든 열고 Anthropic 계정으로 인증
3. 인증 후 브라우저에 코드가 표시됩니다 — `REAUTH:<code>` 형식으로 채팅에 붙여넣기
4. 확인 버블이 나타나고 에이전트가 정상적으로 재개됩니다

계정 전환이나 재인증 플로우 테스트를 위해 에이전트의 Claude 계정에서 로그아웃하려면, 같은 단일 에이전트 룸에서 `/logout`을 입력합니다.

> 두 명령 모두 AI 에이전트가 정확히 1개인 룸으로 제한됩니다. Claude 인증 정보는 머신 전체에 적용되므로, 재인증은 해당 머신의 모든 에이전트에 영향을 미칩니다.

### 작업 디렉터리

각 에이전트에는 하나 이상의 **작업 디렉터리**가 있습니다 — 에이전트의 Claude 세션이 실행되는 폴더입니다. 다음이 가능합니다:

- **설정 > AI Agent**에서 에이전트를 선택하여 작업 디렉터리 확인 (작업 디렉터리 카드에 표시)
- UI 또는 API로 새 작업 디렉터리 추가
- 룸 생성 시 특정 작업 디렉터리 지정

**CLAUDE.md 자동 가져오기:** 에이전트가 룸에 연결되면 Stoa는 작업 디렉터리에 git으로 추적되지 않는 `CLAUDE.md` 파일이 있는지 확인합니다. 있으면 해당 파일 내용이 룸의 **시스템 프롬프트**로 자동 가져와져 첫 번째 메시지부터 에이전트에게 프로젝트 컨텍스트를 제공합니다. CLAUDE.md가 git으로 추적되는 경우(저장소에 커밋된 경우)는 건드리지 않고 가져오지 않습니다. 룸에 작업 디렉터리가 여러 개 있는 경우 각 소스별 헤더와 함께 내용이 결합됩니다. 가져오기가 발생하면 룸에 시스템 이벤트가 전송됩니다.

### 클라이언트 버전 관리

각 에이전트는 **클라이언트 버전**(예: `v0.2.2`)을 서버에 보고합니다. **설정 > AI Agent**의 에이전트 사이드바 행에서 버전을 확인할 수 있습니다. 어떤 에이전트가 최신 클라이언트 코드를 실행 중인지 확인할 수 있습니다.

### 에이전트 컨트롤

**설정 > AI Agent**에서 에이전트를 선택하면 상세 헤더에 액션 버튼이 표시됩니다:

- **재스캔** — 에이전트의 작업 디렉터리, 스킬, 하네스 가용성 재스캔
- **강제 업데이트** — 에이전트가 즉시 클라이언트 업데이트를 확인하도록 강제 (일반적으로 2분마다 확인)
- **삭제** — 에이전트 등록 해제 (확인 필요)

**세션 압축** — 에이전트의 대화 기록을 압축하여 컨텍스트 크기를 줄입니다. 스레드 패널을 열고 패널 헤더의 압축 버튼 (↕ 아이콘)을 클릭하세요. 압축 중 스레드 패널 안에 진행 표시줄이 나타나며 에이전트는 이전 컨텍스트를 요약하고 원활하게 계속합니다. 대화가 매우 길어지고 응답 품질이 저하되기 시작할 때 유용합니다. Codex 하네스 세션에서는 압축이 지원되지 않습니다 — 압축을 클릭하면 토스트 오류(`compact not supported for codex harness`)가 표시됩니다.

### 자동 압축 (Auto-Compact)

Stoa는 수동 개입 없이 에이전트 세션을 자동으로 압축합니다. 두 가지 메커니즘이 병렬로 실행됩니다:

- **트리거별 확인** — 에이전트가 응답할 때마다 Stoa는 세션 파일 크기를 확인합니다. 설정된 압축 임계값(기본 500 KB, Settings → Server에서 변경 가능)을 초과하면 에이전트는 답변을 보낸 직후 `/compact`를 실행하고 서버에 알립니다. 사용자는 먼저 응답을 받고 압축은 백그라운드에서 진행됩니다.
- **백그라운드 워커** — 60분마다 에이전트는 자신의 머신에 열려 있는 모든 세션을 스캔하고 설정된 압축 임계값을 초과하는 세션을 압축합니다. Stoa 룸에서 활성화되지 않은 로컬 세션도 정리됩니다.

자동 압축이 실행되면 스레드 패널 안에 압축 진행 표시줄이 나타나고(수동 압축과 동일) 압축 마커가 스레드의 메시지 기록에 저장됩니다. 마커는 페이지 새로 고침 후에도 유지됩니다.

두 메커니즘 모두 Codex 하네스로 실행 중인 세션을 건너뜁니다 — Codex는 압축을 지원하지 않습니다.

### 자율적 메시지

에이전트는 사람의 메시지 트리거 없이 자발적으로 룸에 메시지를 보낼 수 있습니다. 이는 비동기적으로 완료되는 백그라운드 작업(긴 빌드 완료, 예약된 확인, 모니터링 알림 등)에 유용합니다.

이 헬퍼 함수는 모든 에이전트의 Claude Code 환경 내에서 사용할 수 있습니다:

```javascript
await sendProactiveMessage(roomId, '빌드 완료 — 오류 0개, 경고 3개.');
```

- `roomId`는 모든 트리거 시 에이전트의 프롬프트에 자동으로 주입됩니다([아키텍처 개요](#아키텍처-개요) 참조). 따라서 에이전트는 항상 어느 룸에 게시할지 알고 있습니다 — ID를 명시적으로 전달할 필요가 없습니다
- 메시지는 에이전트의 시크릿으로 인증됩니다 — 등록된 에이전트만 이 엔드포인트를 호출할 수 있습니다
- 메시지는 일반 에이전트 응답처럼 룸 채팅에 나타납니다

**API 엔드포인트**(외부 스크립트 또는 사용자 정의 통합용):

```
POST /api/rooms/:roomId/message
Headers:
  X-Agent-Id: <에이전트 숫자 ID>
  X-Agent-Secret: <에이전트 시크릿>
Body: { "content": "메시지 내용" }
```

### 에이전트 스킬

스킬은 에이전트의 Claude Code 환경에서 사용 가능한 슬래시 명령어입니다(예: `/stoa-audit`, `/deploy`). 에이전트의 작업 디렉터리에서 자동 감지되어 설정 패널에 표시됩니다.

스킬은 **작업 디렉터리 범위**로 제한됩니다 — 특정 작업 디렉터리로 룸을 만들면 해당 작업 디렉터리(프로젝트/로컬 범위)의 스킬과 전역 스킬만 사용 가능합니다. 서로 다른 프로젝트 간 스킬 충돌을 방지합니다.

채팅에서 슬래시 명령어를 직접 입력하여 스킬을 호출할 수 있습니다:
```
/skill-name
```

## 워크스페이스 패널 (파일 편집)

워크스페이스 패널은 채팅 오른쪽에 표시되는 코드 뷰어 및 파일 브라우저입니다. AI 에이전트 머신의 파일을 탐색·미리보기·편집할 수 있습니다(원격 서버 포함).

### 패널 열기

채팅 헤더의 **패널 전환 버튼**(분할 창 아이콘)을 클릭합니다. 오른쪽에 패널이 열리며 드래그 핸들로 크기를 조절할 수 있습니다.

### 파일 트리 (Files 탭)

**Files** 탭에는 룸 작업 디렉토리의 프로젝트 디렉토리 트리가 표시됩니다. 파일을 클릭하여 열 수 있습니다. 폴더는 클릭으로 펼치기/접기.

### 코드 뷰어

텍스트 파일은 **구문 강조**(highlight.js), **줄 번호**, 어두운 코드 배경으로 열립니다. 상단 경로 탐색(breadcrumb)에 파일 경로가 표시됩니다.

### 파일 편집

텍스트 파일의 **Edit** 버튼을 클릭하여 편집 모드로 진입합니다. **CodeMirror 6** 구문 강조 지원(JavaScript, TypeScript, Python, JSON, HTML, CSS, Markdown).

- **저장**: `Ctrl+S`(`Cmd+S`) 또는 Save 버튼
- **전체 화면**: 확장 버튼으로 에디터 전체 너비 사용(채팅 패널 숨김)
- **충돌 감지**: 편집 중 파일이 변경되면 다시 로드 또는 덮어쓰기 대화 상자 표시
- **자동 저장**: 저장하지 않은 편집은 브라우저에 저장되며, 다시 열 때 복구 프롬프트 표시
- **키보드 단축키**: `Ctrl+/`(주석 토글), `Ctrl+Shift+D`(줄 복제), `Alt+Shift+↑/↓`(줄 복사), `Tab`(들여쓰기)

CodeMirror 로드에 실패하면(CDN 접근 불가 등) 일반 텍스트 영역으로 폴백됩니다.

### 파일 작업 (컨텍스트 메뉴)

파일 트리에서 파일이나 폴더를 우클릭(태블릿에서는 길게 누르기)하여 컨텍스트 메뉴를 열 수 있습니다:

- **새 파일** — 선택한 폴더에 새 파일 생성
- **새 폴더** — 새 디렉토리 생성
- **이름 바꾸기** — 파일 또는 폴더 이름 변경
- **삭제** — 파일 삭제(확인 대화 상자 포함)

### Markdown 미리보기

`.md` 파일은 제목, 목록, 코드 블록, 표, 링크가 포함된 형식화된 마크다운으로 렌더링됩니다.

### 이미지 미리보기

이미지 파일(PNG, JPG, GIF, WebP, SVG)은 가운데 정렬된 미리보기로 표시됩니다. 원격 에이전트의 경우 에이전트의 WebSocket 연결을 통해 이미지를 가져옵니다.

### Git 차이 (Git 탭)

**Git** 탭에는 미커밋 변경 사항(`git diff`)이 초록/빨강 줄 강조, 파일 헤더, 변경 통계와 함께 표시됩니다.

### 클릭 가능한 파일 경로

AI 에이전트가 메시지에서 파일 경로(예: `/home/user/project/file.py`)를 언급하면 그 경로가 **클릭 가능**해집니다. 클릭하면 워크스페이스 패널에서 파일이 열립니다. 백틱 코드 블록과 코드 펜스 내의 경로에서도 동작합니다.

### 파일 다운로드

파일 트리의 파일에 마우스를 올리면 **다운로드 버튼**(화살표 아이콘)이 나타납니다. 클릭하면 로컬 기기에 다운로드됩니다. 원격 에이전트 파일도 WebSocket을 통해 가져와 브라우저 다운로드로 전달됩니다.

### 원격 파일 탐색

워크스페이스는 로컬과 원격 에이전트 모두에서 동작합니다. 원격 에이전트의 경우 파일 작업이 에이전트의 WebSocket 연결을 통해 프록시됩니다. 태블릿과 스마트폰을 포함한 모든 기기에서 에이전트가 실행 중인 모든 머신의 파일을 탐색할 수 있습니다.

## 에이전트 패널

**에이전트 패널**은 룸 참가자와 서브 에이전트를 보고 관리하는 오른쪽 사이드바 팝오버입니다. 오른쪽 사이드바의 **사용자 아이콘**（워크스페이스 버튼과 구분선 사이）을 클릭하여 엽니다.

### 참가자

룸에 있는 모든 에이전트를 표시합니다 — 각 행에 아바타, 이름, 유형(AI 또는 사람), 실시간 **온라인/오프라인 상태**가 표시됩니다.

새 에이전트를 추가하려면 섹션 하단의 **Add Agent** 폼을 사용합니다. 드롭다운에서 에이전트를 선택하고 **작업 디렉터리**를 고른 후 **Add Agent**를 클릭합니다. 아직 룸에 없는 에이전트만 표시됩니다.

### 서브 에이전트

두 그룹이 표시됩니다：

- **Linked（연결됨）** — 이미 이 룸에 연결된 서브 에이전트. 각 행에 레이블과 상위 에이전트 이름이 표시됩니다. **Unlink**를 클릭하면 연결을 해제할 수 있습니다.
- **Available（사용 가능）** — 룸의 어떤 에이전트에든 정의되어 있지만 아직 연결되지 않은 서브 에이전트. **Link**를 클릭하면 이 룸에서 활성화됩니다.

> 이는 룸 헤더의 에이전트 인장을 클릭하는 방법의 대안입니다 — 둘 다 동일한 서브 에이전트 링크를 관리합니다.

## 자동화

Stoa는 **Slack, WhatsApp, Email로 트리거되는 자동화**를 지원합니다 — 이벤트가 조건과 일치할 때 자동으로 대상 룸에 프롬프트를 전송하는 규칙입니다.

### 연결 관리

**설정 > 자동화 > 연결**을 열어 연결을 관리합니다. 각 연결은 고유한 자격 증명을 가진 독립적인 라이브 세션입니다.

**+ add connection**을 클릭하여 새 연결을 추가합니다. 먼저 **Provider**를 선택하세요:

**Slack 연결:**
- **Name** — 연결을 식별하는 레이블 (예: "Qiscus 워크스페이스")
- **Token Type** — `bot` (Bot Token `xoxb-...`) 또는 `user` (User Token `xoxp-...`)
- **App Token** (`xapp-1-...`) — Socket Mode WebSocket 연결용
- **Bot / User Token** — 이벤트를 수신하고 API 호출을 수행하는 토큰

Slack 앱 토큰 생성 방법은 [Slack 설정 가이드](doc-slack-setup)를 참조하세요.

**WhatsApp 연결:**
- **Name** — 연결을 식별하는 레이블 (예: "Support WA")
- **Phone Number** — 선택 사항, 참조용
- **Max Media Size (MB)** — 다운로드할 미디어 파일의 최대 크기 (기본값: 100 MB)

**Connect & Show QR**을 클릭하면 WhatsApp 세션이 시작되고 QR 코드 모달이 열립니다. WhatsApp 앱으로 QR을 스캔하여 인증합니다. 연결되면 카드에 연결된 전화의 JID와 초록색 점이 표시됩니다. 세션이 만료되면 **Show QR**로 새 QR 코드를 표시합니다.

**이메일(IMAP) 연결:**
- **Name** — 연결을 식별하는 레이블 (예: "Gmail 개인")
- **Preset** — **Gmail** (`imap.gmail.com:993` 자동 설정) 또는 **Custom IMAP** (모든 IMAP 서버)
- **IMAP Host / Port** — Custom IMAP에서만 표시. 서버 주소와 포트 입력
- **Email address** — 계정 사용자 이름 (예: `you@gmail.com`)
- **App Password** — Gmail의 경우 일반 비밀번호가 아닌 앱 비밀번호를 사용해야 합니다. Google 계정 → 보안 → 2단계 인증 → 앱 비밀번호에서 생성하세요. 2단계 인증이 활성화되어 있어야 합니다. 다른 제공업체는 계정 비밀번호 또는 IMAP 전용 비밀번호를 사용합니다.
- **Folder** — 모니터링할 메일함 폴더 (기본값: `INBOX`)
- **Allowed senders** — 줄당 하나의 이메일 주소 또는 도메인 와일드카드 (예: `boss@example.com`, `*@company.com`). **최소 1개 입력 필수** — 허용 발신자가 없는 연결은 자동화를 트리거하지 않습니다 (기본값: 차단). 누구나 받은 편지함으로 이메일을 보낼 수 있으며, 이메일 내용이 에이전트를 조작하려 시도할 수 있습니다 (프롬프트 인젝션).
- **Require sender verification** — 활성화 시 (기본값: 켜짐), DMARC 또는 DKIM 검증에 실패한 이메일은 자동으로 삭제됩니다. 스푸핑된 `From` 주소가 허용 목록을 우회하는 것을 방지합니다.
- **Sender name** *(선택 사항)* — 발신 답장 이메일의 `From` 헤더에 표시될 이름 (예: `지원팀`). 비워두면 답장하는 에이전트의 이름이 대체값으로 사용됩니다. 발신 주소는 항상 Gmail 계정으로 유지되며 표시 이름만 변경됩니다.

  > **팁:** 계정 소유자의 이름처럼 알아볼 수 있는 이름을 설정하면 수신자가 혼동하지 않고 이메일 전달률 향상에도 도움이 됩니다.

이메일 연결은 **IMAP IDLE**을 사용하여 실시간 배달합니다 — 서버에서 메일 제공업체로의 완전한 아웃바운드 연결이므로 공개 엔드포인트나 방화벽 규칙이 필요하지 않습니다. Tailscale 환경에서도 원활하게 작동합니다.

수신 이메일은 자동화 규칙을 트리거합니다. 에이전트는 API를 사용하여 해당 이메일에 **답장**을 보낼 수도 있습니다 (아래 [이메일 답장](#이메일-답장) 참조).

> **Outlook / Microsoft 365:** 이 버전에서는 지원되지 않습니다 — Microsoft가 기본 IMAP 인증을 비활성화했습니다. OAuth2 지원은 향후 릴리스에서 계획되어 있습니다.

**연결 테스트:** 저장 전에 **Test connection**을 클릭하여 자격 증명과 연결을 확인하세요. 편집 모드에서는 비밀번호 필드를 비워두면 저장된 (암호화된) 비밀번호가 사용됩니다 — 초기 설정 후에는 저장된 비밀번호가 다시 표시되지 않습니다.

**비밀번호 저장:** 비밀번호는 서버에 암호화되어 저장되며 API를 통해 반환되지 않습니다.

각 연결 카드에는 현재 상태가 표시됩니다: **connecting**, **connected**, **disconnected**, 또는 **error**. 실패한 연결을 재시도하려면 **reconnect** 버튼을, 관리하려면 **edit**과 **delete** 버튼을 사용하세요.

### 자동화 규칙 만들기

하나 이상의 연결이 활성화되면 **+ new rule**을 클릭하여 규칙을 만듭니다:

- **이름** — 규칙의 설명 레이블
- **연결** — 이 규칙을 실행할 연결, 또는 모든 연결의 이벤트와 일치하는 **Any connection**
- **트리거 이벤트** — 규칙을 실행할 이벤트 (제공자에 따라 다름):
  - *Slack:* `message`, `message.groups`, `mention`, `reaction_added`
  - *WhatsApp:* `message` (다이렉트 메시지), `group_message` (그룹 메시지), `group_mention` (그룹에서 봇 태그됨), `message_any` (DM + 그룹)
  - *Email:* `message` (새 이메일 수신)
- **조건** — 이벤트에 대한 선택적 필터: `contains`, `not_contains`, `starts_with`, 또는 `matches_regex`. 여러 조건은 AND로 결합. `matches_regex` 제한: 패턴 최대 200자, 중첩 수량자 거부 (ReDoS 보호), 입력 5,000자에서 잘림, 과도한 백트래킹을 유발하는 패턴은 저장 시 400 오류로 거부. 조건 필드는 제공자마다 다릅니다:
  - *Slack:* `message text`, `full text`, `slack_user`, `slack_channel`, `slack_bot_id`
  - *WhatsApp:* `message text`, `sender JID`, `chat ID`
  - *Email:* `from address`, `subject`, `has attachments`
- **대상 룸** — 프롬프트를 받을 Stoa 룸
- **프롬프트 템플릿** — 룸으로 보낼 메시지. 사용 가능한 변수:
  - *Slack:* `{{slack_message_text}}`, `{{slack_message_link}}`, `{{slack_user}}`, `{{slack_channel}}`, `{{extracted_url}}`, `{{slack_thread_ts}}`
  - *WhatsApp:* `{{wa_message_text}}`, `{{wa_sender}}`, `{{wa_sender_name}}`, `{{wa_chat_id}}`, `{{extracted_url}}`
  - *Email:* `{{email.from}}`, `{{email.from_name}}`, `{{email.subject}}`, `{{email.body}}`, `{{email.date}}`, `{{email.has_attachments}}`

  > **보안 주의 사항 (Email):** `{{email.body}}`는 신뢰할 수 없는 데이터입니다. 특별히 작성된 이메일이 에이전트를 조작하려 시도할 수 있습니다. 프롬프트에서 구분자로 감싸서 데이터임을 명확히 하는 것을 권장합니다.
- **WhatsApp에 답장** *(WhatsApp 연결만 해당)* — 활성화되면 서버가 발신자 정보, 채팅 ID, 에이전트 지침이 포함된 WhatsApp 컨텍스트 블록을 프롬프트에 삽입합니다. 에이전트는 출력에서 `[wa:reply]` 마커를 사용하여 WhatsApp에 답장할 수 있습니다:

  ```
  [wa:reply]답장 메시지를 여기에 입력[/wa:reply]
  ```

  서버는 마커를 감지하고 텍스트를 WhatsApp 발신자에게 전송하며, 룸 메시지에서 마커를 제거하고 발신 메시지를 기록합니다. 에이전트가 마커를 사용하지 않으면 서버는 기존처럼 전체 AI 응답을 전송합니다.

  컨텍스트 블록은 **메시지 기록 API**에 대해서도 에이전트에게 알려줍니다 — 에이전트는 다음을 통해 최근 채팅 기록을 읽을 수 있습니다:

  ```
  curl <base_url>/api/automations/connections/<connId>/messages?chatId=<chatId>&limit=20
  ```

  룸의 CLAUDE.md를 사용하여 에이전트에게 언제 기록을 읽고 어떻게 응답할지 지시하세요.

- **답장 모니터링 (Watch Replies)** *(Slack 및 Email 연결)* — 활성화되면 동일한 대화 스레드의 후속 메시지가 새 Stoa 스레드를 만들지 않고 기존 스레드로 라우팅됩니다.

  *Slack:* 이 자동화를 트리거한 Slack 스레드에 달리는 답장이 동일한 Stoa 스레드로 전달됩니다. 각 답장은 다음 형식으로 수신됩니다:

  ```
  [New Reply on Thread]: 발신자_이름 (발신자_ID) - 메시지 내용
  ```

  같은 Slack 스레드에서 다른 자동화 규칙이 트리거되어도 기존 Stoa 스레드에 추가됩니다.

  *Email:* `In-Reply-To` 또는 `References` 헤더가 동일한 연결의 기존 메시지와 일치하는 수신 이메일은 기존 Stoa 스레드로 라우팅됩니다. 원래 이메일과 동일한 발신자의 답장만 허용되며, 다른 발신자의 이메일은 새 스레드를 만듭니다. 이를 통해 에이전트는 다중 턴 이메일 교환에서 전체 대화 컨텍스트를 유지할 수 있습니다.

  시스템 프롬프트에 지시가 없는 한 에이전트는 후속 메시지에 자동으로 응답하지 않습니다. 기본값: 비활성.

  자동화의 트리거 조건과 일치하는 수신 답장은 룸 피드에도 표시됩니다 — [스레드 브로드캐스트](#스레드-브로드캐스트-thread-broadcast)를 참조하세요.

### 활성화 / 비활성화

각 규칙에는 활성화/비활성화 토글이 있습니다. 비활성화된 규칙은 이벤트가 조건과 일치해도 실행되지 않습니다.

### 이메일 답장

룸의 에이전트는 자동화를 트리거한 이메일에 답장을 보낼 수 있습니다. 엔드포인트 전체 사양은 **Docs > Stoa API**에 있습니다 — 요약:

```
POST /api/rooms/{roomId}/email-reply
{"thread_id": <id>, "body": "일반 텍스트 답장 내용"}
```

서버가 모든 것을 자동으로 처리합니다: 수신자는 항상 원래 발신자(허용 목록에 대해 재검증), 제목에는 `Re:` 접두사 추가(이후 답장에서 중복되지 않음), `In-Reply-To` / `References` 헤더로 수신자 메일 클라이언트에서 올바른 스레드 연결이 보장되며, `From` 표시 이름은 연결의 **Sender name** 필드에서 가져옵니다(에이전트 이름으로 대체). 에이전트는 자격 증명을 절대 다루지 않습니다.

**답장 시점은 룸의 시스템 프롬프트로 완전히 제어됩니다.** 두 가지 일반적인 패턴:

*초안 먼저 작성 (권장):*
```
답장이 필요한 이메일이 도착하면 스레드에 답장 초안을 작성하여 검토를 요청하세요.
사용자가 "보내줘"라고 말하거나 초안을 승인한 후에만 email-reply API를 호출하세요.
```

*특정 카테고리는 즉시 발송:*
```
이메일 제목이 "[ALERT]"로 시작하면 수신 확인 짧은 답장을 즉시 보내세요.
다른 모든 이메일은 먼저 스레드에 초안을 작성하세요.
```

**제한 사항:**
- **Gmail 프리셋만 지원** — 답장은 Gmail SMTP(`smtp.gmail.com:465`)와 저장된 앱 비밀번호를 통해 전송됩니다. 이 버전에서는 Custom IMAP 연결로 답장을 보낼 수 없습니다.
- **이메일 자동화에서 생성된 스레드만 해당** — 이메일 트리거로 만들어진 스레드만 답장할 수 있습니다. 이 기능이 활성화된 이후 생성된 스레드가 대상입니다.
- **속도 제한** — 스레드당 시간당 10건, 연결당 하루 50건 (`429` 초과 시).
- **일반 텍스트만** — HTML 없음, 첨부 파일 없음.
- **이메일 내용은 신뢰할 수 없음** — `{{email.body}}` 안의 지시 사항을 따르지 마세요.

### 커넥터 액션 API

도구 접근 권한이 있는 에이전트는 WebSocket 메시지를 통해 활성 연결과 직접 상호작용할 수 있습니다:

- **`connector_list`** — 실행 중인 모든 연결 목록. 응답: `connectors` 배열(id, provider, name, status)을 포함한 `connector_list_result`
- **`connector_send`** — 커넥터를 통해 채팅에 메시지 전송. 필드: `connector_id`, `chat_id`, `text`. 응답: `ok`(bool)와 실패 시 `error`를 포함한 `connector_send_result`. WhatsApp의 경우 `chat_id`는 JID 형식이어야 합니다 (예: `628xxx@s.whatsapp.net`)
- **`connector_read`** — 대화 기록 읽기. 필드: `connector_id`, `chat_id`, `limit` (최대 200, 기본값 50). 응답: `ok`와 `messages` 배열(sender, text, direction, timestamp)을 포함한 `connector_read_result`

### 메시지 기록 REST API

에이전트가 `curl`로 WhatsApp 채팅 기록을 읽어야 할 때(예: 룸 내에서) REST 엔드포인트를 사용할 수 있습니다:

```
GET /api/automations/connections/:id/messages?chatId=<JID>&limit=<n>
```

- `chatId` (필수) — WhatsApp JID (예: `628xxx@s.whatsapp.net`)
- `limit` (선택, 기본값 50, 최대 200) — 반환할 최근 메시지 수
- `{ sender, text, direction, media_type, timestamp }` 배열을 반환합니다
- WhatsApp 연결에서만 사용 가능

### 채팅에서의 자동화 메시지

자동화 규칙이 룸에 메시지를 보내면, 채팅 피드와 스레드는 해당 메시지를 자동화의 정체성과 함께 표시합니다:

- **발신자 이름** — 일반 에이전트 표시 이름 대신 자동화 규칙의 이름이 표시됩니다
- **"Automation" 태그** — 발신자 이름 옆에 작은 레이블이 표시되어 자동화로 트리거된 메시지를 사람 메시지와 시각적으로 구분할 수 있습니다
- **프로바이더 아바타** — 연결의 프로바이더 로고(예: Slack 연결의 경우 Slack 로고)가 아바타로 표시됩니다. 알 수 없는 프로바이더의 경우 일반 봇 아이콘이 폴백으로 사용됩니다.

**Watch Reply 전달 (Slack 및 Email):** *Watch Replies*가 활성화된 경우, 기존 Stoa 스레드로 라우팅되는 후속 메시지는 원래 스레드를 트리거한 자동화의 정체성을 상속합니다. Slack의 경우 `[New Reply on Thread]: ...`로 표시됩니다. 루트 메시지가 이 기능 도입 이전 메시지로 자동화 메타데이터가 없는 경우, 답글은 "Slack"(또는 "Email")과 공급자 로고로 표시됩니다 — 사람 메시지로는 표시되지 않습니다.

**삭제된 자동화:** 자동화 규칙이 메시지를 보낸 후 삭제되더라도 해당 메시지는 발신자 이름과 프로바이더 로고를 스냅샷으로 유지합니다. 규칙 이름과 프로바이더는 각 메시지에 저장되므로, 규칙을 삭제해도 기록 표시에 영향을 주지 않습니다.

이 기능 도입 *이후*에 전송된 메시지만 자동화 정체성을 갖습니다. 그 이전의 자동화 메시지는 기존과 같이 표시됩니다.

## 설정

Stoa는 앱 가장 왼쪽에 **세로형 사이드바 내비게이션**을 사용합니다. 사이드바는 아이콘만 표시(너비 44 px)되며, 호버하면 200 px로 확장되어 텍스트 레이블이 나타납니다. 아이콘을 클릭하여 섹션을 전환합니다. 모바일(좁은 화면)에서는 사이드바가 숨겨집니다.

내비게이션 항목(위에서 아래): **Inbox**(룸 목록), 구분선, 그리고 설정 섹션: **AI Agent**, **Server**, **General**, **Docs**, **Platforms**, **Automation**, **Usage**, **Doctor**.

### AI Agent

모든 AI 에이전트를 관리하는 2패널 레이아웃. 왼쪽 사이드바에는 온라인/오프라인 상태별로 그룹화된 검색 가능한 에이전트 목록이 표시되며, 상단에 **+ new agent** 버튼이 있습니다. 에이전트를 클릭하면 오른쪽에 상세 패널이 표시됩니다.

상세 패널 구성:

- **헤더** — 에이전트 아바타(클릭하여 변경), 이름(클릭하여 인라인 편집), 온라인/오프라인 상태, 액션 버튼(rescan, force update, remove)
- **에이전트 카드** — 백엔드 유형, 언어 선택기, 이름 필드, 플랫폼 선택기, 하네스 선택기, 재설치용 설치 명령어
- **시스템 프롬프트** — 에이전트가 참여하는 모든 룸에 적용되는 에이전트별 시스템 프롬프트. 서브 에이전트는 자체 시스템 프롬프트를 가지며 이를 상속하지 않습니다
- **서브 에이전트 카드** — 이 에이전트에 정의된 모든 서브 에이전트(추가/편집/삭제/토글 제어)
- **작업 디렉터리 카드** — 이 에이전트에 등록된 작업 디렉터리의 읽기 전용 목록

### 서버

- **공개 URL** — 에이전트와 다른 디바이스가 서버에 접근하는 URL (Tailscale/원격 설정에서 중요)
- **포트** — 서버 포트 변경 (재시작 필요; [포트 변경 가이드](doc-port) 참조)
- **최대 AI 턴 수** — 사람 메시지당 에이전트 응답 최대 수 (무한 루프 방지)
- **동시 세션** — 에이전트가 병렬로 응답할 수 있는 룸 수 (즉시 적용, 재시작 불필요)
- **세션 유휴 TTL** — 유휴 AI 세션이 메모리를 해제하기 위해 자동으로 닫히기까지의 시간(분) (기본값: 5분)
- **정리 시각** — 일일 업로드 정리 실행 시각 (24시간 형식)
- **최대 파일 보관 기간** — 업로드 파일이 정리되기까지의 보관 시간 (시간 단위)

**서버 재시작** — 서버 탭에는 재시작 카드도 표시됩니다. Stoa를 관리하는 프로세스 매니저(예: `running via launchd`)와 **restart server** 버튼이 표시됩니다. launchd, PM2, systemd, supervisord로 관리되는 경우 버튼이 활성화되며, 프로세스 종료 후 프로세스 매니저가 자동으로 재시작합니다. Docker 또는 알 수 없는 환경에서는 버튼이 비활성화됩니다(외부에서 컨테이너 또는 프로세스를 재시작하세요). **restart server** 클릭 → 대화 상자 확인 → 서버가 연결된 모든 에이전트와 브라우저에 알림을 보낸 후 종료합니다. 브라우저는 약 2~3초 이내에 자동으로 재연결되며 연결이 복원되면 "Server restarted"가 잠시 표시됩니다.

### 플랫폼

기본 제공 Claude 모델 외에 외부 AI 모델 제공자를 설정합니다. **+ add platform**을 클릭하여 새 제공자를 등록합니다:

- **Type** — **Ollama Cloud** (내장 프록시, URL 불필요) 또는 **Custom Platform** (OpenAI 호환 API)
- **Name** — 플랫폼 이름 (예: "My OpenRouter")
- **Base URL** — Custom Platform에 필요 (예: `https://openrouter.ai/api/v1`)
- **API Key** — 해당 제공자의 API 키

새 플랫폼의 경우 **add & discover**를 클릭하여 저장과 탐색을 한 번에 할 수 있습니다. 기존 플랫폼은 **discover models**를 클릭하여 재탐색합니다. Discovery는 모델별 기능(vision 👁 및 도구 호출 ⚙)을 감지합니다. 도구 호출 미지원 모델도 포함되어 사용 가능하지만 텍스트 전용 모드로 동작합니다.

**모델 활성화/비활성화**: Discovery 후 발견된 모든 모델의 체크리스트가 표시됩니다. 룸 선택기에 표시할 모델만 체크하고 **update**를 클릭하여 저장하세요. **select all / deselect all**로 일괄 전환도 가능합니다. 선택은 세션 간 유지되며 재탐색 시 자동 업데이트됩니다.

API 키는 서버에 저장되며 Settings 편집 폼에서만 브라우저로 반환됩니다 (싱글유저 앱이므로 접근 권한은 본인만 갖습니다).

**지원 제공자** — OpenAI 호환 API 엔드포인트라면 어디든 사용 가능합니다:
- **Ollama Cloud** — "Ollama Cloud" 타입 선택 (내장 프록시, 키 로테이션, 40+ 모델, 최대 480B)
- **Local Ollama** — `http://localhost:11434/v1` (무료, 프라이빗, 오프라인 가능 — [Ollama 설정 가이드](doc-ollama) 참조)
- **OpenRouter** — `https://openrouter.ai/api/v1`
- **Together AI** — `https://api.together.xyz/v1`
- **Groq** — `https://api.groq.com/openai/v1`

### 커스텀 Claude 모델

Anthropic이 기본 제공 목록에 없는 새 모델을 출시하면 서버를 업데이트하지 않고도 추가할 수 있습니다. **Settings > Platforms**의 **claude models** 카드로 스크롤하세요.

Claude CLI 바이너리를 가진 에이전트가 온라인 상태이면, 카드에 **Detected from Claude CLI v*X*** 스트립이 표시되어 각 패밀리에서 이미 등록된 최신 항목보다 새로운 모델 ID의 칩을 클릭할 수 있습니다. 칩을 클릭하면 모델 ID와 레이블 필드가 자동으로 채워집니다 (레이블 자동 생성, 예: _Haiku 5.5_, 편집 가능). **add model**을 클릭하여 저장 — 자동 저장은 되지 않습니다. 이전 모델 ID는 수동으로 입력할 수 있습니다. CLI를 보고한 에이전트가 없으면 스트립에 연결을 안내하는 메시지가 표시됩니다.

- **추가** — 모델 ID(예: `claude-haiku-5-5`)와 선택적 표시 레이블(최대 40자)을 입력하고 **add model**을 클릭합니다. 모델이 즉시 룸 모델 드롭다운에 **custom** 태그와 함께 표시됩니다.
- **삭제** — 커스텀 모델 행의 ×를 클릭합니다. 이미 해당 모델을 사용 중인 룸은 설정을 유지합니다. 새 선택에만 영향을 줍니다.

모델 ID 형식: `claude-`로 시작하고 소문자, 숫자, 점, 또는 하이픈이 이어져야 합니다 (정규식: `^claude-[a-z0-9][a-z0-9.-]{1,62}$`). 중복되거나 잘못된 형식의 ID는 인라인으로 거부됩니다. 최대 20개의 커스텀 항목.

### Usage

**Usage** 탭은 AI 토큰 소비량을 보여주는 개인 분석 대시보드입니다. 모든 데이터는 로컬 캘린더 날짜로 집계됩니다 — 탭을 열 때마다 브라우저의 시간대가 전송되므로 날짜 경계, 피크 시간, 연속 기록이 UTC가 아닌 로컬 자정에 맞춰집니다.

상단에 두 개의 세그먼트 컨트롤이 있습니다:

- **View** — **Summary**와 **Model** 전환
- **Period** — **All**, **30d**, **7d** — 아래 모든 통계를 해당 기간으로 필터링

**Summary 뷰**는 통계 카드 그리드를 표시합니다: 메시지당 평균 토큰, 총 메시지 수, 총 토큰(입력 + 출력 + 캐시 읽기 + 캐시 생성), 활동 일수, 현재 및 최장 연속 기록(연속 활동 일수, 현재 기록은 오늘부터 거슬러 계산), 피크 시간(로컬 시간대), 입력/출력 토큰, 캐시 히트, 예상 총 비용(USD), 가장 많이 사용한 모델.

카드 아래에는 최근 26주를 포괄하는 **활동 히트맵**이 있습니다. 각 셀은 하루를 나타내며, 셀이 진할수록 토큰이 많다는 의미입니다. 셀에 마우스를 올리면 정확한 날짜와 토큰 수가 표시됩니다. 레이아웃은 가변적이어서 가로 스크롤 없이 모바일 화면에 맞게 축소됩니다.

**Model 뷰**는 모델별로 사용량을 분류합니다:

- **누적 막대 차트**가 일일 토큰 양을 표시하며, 각 모델은 다른 색상으로 구분됩니다
- 아래의 **모델 목록**은 각 모델의 입력/출력 토큰 합계와 비율을 표시합니다

모든 수치는 읽기 전용이며 탭을 다시 열거나 기간을 변경할 때마다 갱신됩니다.

## 공개 배포

Stoa는 로컬 머신 외부에서 세 가지 구성으로 접근할 수 있습니다:

### (A) Tailscale만 사용
머신의 Tailscale IP를 사용하여 Tailscale 네트워크의 모든 장치에서 Stoa에 접근합니다. 추가 설정이 필요 없습니다. 에이전트와 설치 명령어가 올바른 주소를 사용하도록 **설정 > 서버**에서 **Public URL**을 `http://<tailscale-ip>:<port>`로 설정하세요.

### (B) Cloudflare 터널 (동일 머신)
Stoa와 같은 머신에서 `cloudflared tunnel`을 실행하여 방화벽 포트를 열지 않고 공개 도메인으로 노출합니다. 기본적으로 cloudflared는 이미 신뢰된 `localhost`에서 연결합니다. **Public URL**을 터널 URL(예: `https://stoa.example.com`)로 설정합니다. 다음 경로에 대한 Cloudflare 캐시 우회 규칙을 추가하세요:
- 캐시 우회 경로: `/uploads/*` 및 `/connector-media/*`

> **Cloudflare Access + 에이전트:** 에이전트 환경에 `STOA_CF_ACCESS_CLIENT_ID`와 `STOA_CF_ACCESS_CLIENT_SECRET`을 설정하면 Cloudflare Access 서비스 토큰을 전송할 수 있습니다. 토큰은 Stoa 오리진에만 전송되며, 모델 공급자나 다른 호스트에는 전송되지 않습니다. 자식 세션(Claude Code, Codex)은 루프백 프록시 URL을 받아 토큰이 프롬프트에 들어가지 않고 Access를 통해 Stoa에 접근할 수 있습니다. 이 변수들이 설정되지 않으면 동작은 변경되지 않습니다. **권장:** 에이전트에는 Tailscale을 우선 사용하고, Tailscale을 사용할 수 없을 때만 CF Access 토큰을 사용하세요.

### (C) VPS + 역방향 프록시 + 도메인
공개 도메인과 TLS를 갖춘 VPS에서 nginx, Caddy 또는 다른 역방향 프록시 뒤에 Stoa를 실행합니다.

**환경 변수:**

| 변수 | 설명 |
|------|------|
| `STOA_TRUSTED_PROXIES` | 신뢰할 프록시의 IP/CIDR (쉼표 구분). 기본값: `127.0.0.1/32,::1/128` (localhost). `none`으로 설정하면 어떤 프록시도 신뢰하지 않음. |
| `STOA_ALLOWED_ORIGINS` | 허용된 오리진 (예: `https://stoa.example.com`). 프록시가 `X-Forwarded-Host` 없이 `Host` 헤더를 변경하는 경우 필요. |

**신뢰 작동 방식:** 클라이언트 IP와 HTTPS 상태는 요청이 신뢰된 프록시에서 온 경우에만 프록시 헤더(`CF-Connecting-IP`, `X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto`)에서 읽습니다. 역방향 프록시는 이 헤더들을 설정하고 클라이언트로부터의 신뢰되지 않은 헤더는 전달하지 않아야 합니다.

**헤더 설정 — Cloudflare를 사용하지 않는 경우 중요:** Stoa는 클라이언트 IP를 다음 순서로 읽습니다: `CF-Connecting-IP` → `X-Real-IP` → `X-Forwarded-For`. 프록시가 Cloudflare가 **아닌** 경우(예: VPS의 nginx나 Caddy 직접 사용), 프록시는 클라이언트가 전송하는 `CF-Connecting-IP`를 **반드시** 제거해야 합니다. 제거하지 않으면 공격자가 이 헤더를 위조하여 IP별 로그인 속도 제한을 우회할 수 있습니다. 이메일별 제한과 장치 쿠키는 계속 유효합니다.

**nginx:**
```nginx
proxy_set_header CF-Connecting-IP "";
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $remote_addr;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-Host $host;
```

**Caddy:**
```caddy
header_up -CF-Connecting-IP
header_up X-Real-IP {remote_host}
```

> **nginx 앞에 Cloudflare가 있는 경우:** Cloudflare가 nginx 앞에 있으면 `CF-Connecting-IP`를 제거하지 마세요. 대신 [Cloudflare IP 범위](https://www.cloudflare.com/ips/)만 오리진 서버에 접근할 수 있도록 제한하세요.

**HTTPS:** 공개 배포에 필수입니다. HTTPS가 감지되면 세션 쿠키에 `Secure`가 설정되고 HSTS가 자동으로 전송됩니다.

**public_url:** **설정 > 서버**에서 공개 URL(예: `https://stoa.example.com`)을 설정합니다. 에이전트 설치 명령어와 내부 링크에 사용됩니다.

**CSRF 보호:** 세션 쿠키로 인증된 쓰기 요청은 `Origin` 헤더가 검증됩니다. 오리진이 `Host`, `public_url`, 또는 `STOA_ALLOWED_ORIGINS`와 일치하지 않으면 서버가 `403 origin_not_allowed`를 반환합니다. `Origin`을 전송하지 않는 비브라우저 클라이언트(에이전트, API 도구)는 영향을 받지 않습니다.

### 에이전트 권한

에이전트 시크릿(`x-agent-id` / `x-agent-secret`)은 합법적인 에이전트 작업에 필요한 라우트 목록으로 제한됩니다. 이 목록 외의 요청은 `403 {"error":"agent_scope_denied"}`로 거부되고 `[agent-scope] denied actor=<id> METHOD /path`로 기록됩니다.

| 라우트 | 접근 조건 |
|--------|---------|
| `POST /api/rooms/:id/message` | 룸 참가자 |
| `POST /api/rooms/:id/email-reply` | 룸 참가자 |
| `GET/PUT /api/rooms/:id/memory` | 룸 참가자 |
| `GET/PUT /api/rooms/:id/system-prompt` | 룸 참가자 |
| `POST /api/rooms/:id/sub-agent-trigger` | 룸 참가자 |
| `GET /api/rooms/:id/messages` | 룸 참가자 |
| `GET /api/rooms/:id/threads[/:id]` | 룸 참가자 |
| `POST /api/upload/raw` | 유효한 에이전트 |
| `GET /uploads/*, /connector-media/*` | 유효한 에이전트 |
| `GET /api/docs/stoa-api*.md` | 유효한 에이전트 |
| `GET/PUT /api/actors/:id/memory[/MEMORY.md\|USER.md]` | 자신의 액터만 |
| `GET/PUT /api/actors/:id/system-prompt` | 자신의 액터만 |
| `GET/PUT /api/sub-agents/:id/memory` | 소유한 서브에이전트만 |
| `GET /api/automations/connections/:id/messages` | 연결된 자동화 룸 |
| `GET /api/automations` | 유효한 에이전트 (서버가 자신의 룸만 필터링) |
| `POST /api/automations` | 유효한 에이전트 (`target_room_id`는 자신의 룸이어야 함) |
| `PATCH /api/automations/:id` | 소유한 자동화 (`target_room_id`는 자신의 룸으로 유지되어야 함) |
| `DELETE /api/automations/:id` | 소유한 자동화 |
| `GET /api/automations/connections` | 유효한 에이전트 (`id`, `name`, `provider`, `status`만 — 자격 증명 없음) |

에이전트가 자동화를 생성, 업데이트 또는 삭제할 때마다 대상 룸에 영구 시스템 알림이 게시됩니다 (예: *"Ara created automation 'X' (trigger: slack message) · automation"*). 이를 통해 워크스페이스 소유자가 변경 사항을 모니터링하고 필요시 취소할 수 있습니다.

브라우저 세션(세션 쿠키)은 전체 접근 권한을 유지합니다. 범위 적용을 비활성화하려면 서버에 `STOA_AGENT_SCOPE=off`를 설정하세요 — 시작 시 경고가 기록됩니다.

## 아키텍처 개요

```
브라우저  <-->  WebSocket  <-->  server.js  <-->  에이전트 (stoa.js)
                                    |                   |
                                 SQLite DB      Claude Code CLI
                                                  (+ 환경 변수를 통한
                                                   외부 플랫폼 연동)
```

- **server.js** — HTTP + WebSocket 서버. 룸, 메시지, 에이전트 오케스트레이션 관리
- **public/** — 프런트엔드 (빌드 단계 불필요)
- **stoa.js** — 각 에이전트 머신에서 실행되는 에이전트 클라이언트
- **claude-session.js** — Claude Code CLI 서브프로세스 관리
- **codex-session.js** — Codex CLI 서브프로세스 관리. Stoa 자동 업데이트를 통해 배포됩니다(서버 업데이트 시 다운로드, 하네스 전환 시점과 무관)
- **SQLite** — 모든 데이터를 `stoa.db`에 로컬 저장 (성능을 위한 WAL 모드)

모든 AI 모델은 **Claude Code CLI**를 통해 라우팅됩니다. 커스텀 외부 플랫폼(OpenRouter, Together AI 등)의 경우, 서버가 플랫폼별 환경 변수(`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`)를 CLI 프로세스에 전달합니다. **Ollama Cloud**의 경우, 요청은 Stoa 내장 프록시(`/v1/messages`)를 통해 라우팅되며 서버 측에서 API 키 로테이션을 처리합니다 — 에이전트는 Stoa에 연결하고 ollama.com에는 직접 연결하지 않습니다.

**프롬프트의 룸 컨텍스트 주입**: 에이전트가 트리거될 때마다 서버는 에이전트의 시스템 프롬프트에 `Room ID: <id>`를 주입합니다. 이를 통해 에이전트는 항상 자신이 어느 룸에서 동작하는지 알 수 있으며, ID를 명시적으로 전달하지 않고도 `sendProactiveMessage(roomId, ...)` 등의 룸 인식 작업을 수행할 수 있습니다.
